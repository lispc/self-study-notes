# 有限状态机：Mealy/Moore、状态编码与设计实例

> 本书位置：数字电路设计 · 第一部分（基础）· 第 5 章
> 前置知识：第 3 章的组合逻辑设计（真值表、卡诺图化简）；第 4 章的 D 触发器、建立/保持时间与同步时序的基本概念。
> 学习目标：说清楚有限状态机为什么是时序逻辑的"系统化设计方法"；分辨 Mealy 机与 Moore 机的定义、时序差异与工程取舍；掌握"规格 → 状态图 → 状态表 → 状态编码 → 次态/输出逻辑"五步设计流程；比较 binary、one-hot、Gray 三种状态编码的适用场景；最后用一个 1101 序列检测器把全流程完整走一遍，并写出可综合的三段式 Verilog。

---

## 1. 一句话总结

**有限状态机（FSM）把"记住过去"这件事压缩成有限个状态：一组触发器保存当前状态，一块组合逻辑根据当前状态和输入算出次态，另一块组合逻辑产生输出。它是同步时序电路唯一通用的系统化设计方法——任何带记忆的数字系统（协议握手、总线仲裁、CPU 控制器）最终都落成一台或多台 FSM。**

## 2. 什么是有限状态机

第 4 章讲了触发器——它能存一比特。但光有触发器不等于会设计时序电路：面对"检测到 1101 就拉高输出"这类需求，随手摆几个触发器和门电路，稍微复杂一点就会失控。有限状态机给出的答案是：**所有同步时序电路都可以套进同一个三段式结构**：

- **状态寄存器**：$n$ 个 D 触发器，在时钟沿把"次态"锁存为"现态"。这是整机唯一的记忆元件。
- **次态逻辑**：纯组合电路，输入是现态 $S$ 和外部输入 $X$，输出是次态 $S' = f(S, X)$。
- **输出逻辑**：纯组合电路，由现态（以及可能的输入）产生输出 $Y = g(S)$ 或 $g(S, X)$。

用文字画出方框图：

```
                 ┌──────────────┐
   输入 X ──────▶│              │      ┌──────────────┐
                 │  次态逻辑 f   │─────▶│  状态寄存器    │──┐
            ┌───▶│  (组合电路)   │ S'   │  (D 触发器组)  │  │ 现态 S
            │    └──────────────┘      └──────────────┘  │
            │                                            │
            │    ┌──────────────┐                        │
            └───▶│  输出逻辑 g   │◀───────────────────────┘
            X    │  (组合电路)   │────▶ 输出 Y
                 └──────────────┘
```

（输出逻辑的虚线输入 $X$ 只对 Mealy 机存在，见第 3 节。）

为什么说这是"系统化"的方法？三个原因：

- **通用性**：任何同步时序电路，把它的触发器全部抽出来归为一组、剩下的全是组合逻辑，就自动呈现上面的结构。FSM 不是某类电路，而是所有时序电路的规范写法。
- **把"历史"压缩成状态**：时序电路的输出取决于全部过去的输入，这是设计的难点。FSM 的洞察是：过去不需要逐位记住，只需要记住"过去对将来的一切影响"——这就是状态。检测 1101 不需要存下整个输入流，只需要存"目前已经匹配到哪个前缀"，5 个状态就够了。
- **设计变成填表**：一旦状态定义清楚，次态逻辑和输出逻辑就是两张真值表，第 3 章的组合逻辑工具（卡诺图、综合器）直接接管。创造性的工作集中在"定义状态"这一步，其余都是机械操作。

状态数有限是本质约束：$n$ 个触发器最多表示 $2^n$ 个状态。所以 FSM 无法数到任意大的数（那需要计数器/数据通路），它擅长的是**协议与流程**——状态数少、转移结构复杂的问题。到了第 14 章你会看到，CPU 的控制器就是一台大 FSM，而数据通路负责"计数和计算"，两者分工明确。

## 3. Mealy 机 vs Moore 机

两种机的差别只在输出逻辑：

- **Moore 机**：输出只依赖当前状态，$Y = g(S)$。
- **Mealy 机**：输出依赖当前状态和输入，$Y = g(S, X)$。

用同一个例子对比：检测输入流中连续两个 1（"11"），检测到输出 1。

**Moore 版**需要 3 个状态：

- `A`：上一个比特不是 1（初始状态），输出 0；
- `B`：上一个比特是 1，但还没凑够两个，输出 0；
- `C`：已经连续收到两个 1，输出 1。

转移：`A` 收 1 进 `B`、收 0 留 `A`；`B` 收 1 进 `C`、收 0 回 `A`；`C` 收 1 留 `C`（连续 1 还在继续）、收 0 回 `A`。

**Mealy 版**只需要 2 个状态：

- `A`：上一个比特不是 1；
- `B`：上一个比特是 1。

输出挂在转移弧上：`B` 收到 1 的那一拍输出 1（写成弧标注 `1/1`，斜杠前是输入、后是输出），其余所有弧输出 0。也就是 $Y = (S = B)\cdot X$。

时序差异用一串输入看清楚。设输入逐拍为 `0 1 1 0 1 1 0`，初态都是 `A`：

| 拍 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 输入 X | 0 | 1 | 1 | 0 | 1 | 1 | 0 |
| Moore 现态 | A | A | B | C | A | B | C |
| Moore 输出 | 0 | 0 | 0 | 1 | 0 | 0 | 1 |
| Mealy 现态 | A | A | B | B | A | B | B |
| Mealy 输出 | 0 | 0 | 1 | 0 | 0 | 1 | 0 |

两列输出对比就是全部要点：

- **Mealy 提前一拍**：第 3 拍第二个 1 到达的当拍，Mealy 就输出 1；Moore 要等时钟沿把状态推进到 `C`，第 4 拍才输出。这不是谁快谁慢的问题，而是定义如此——Mealy 的输出是输入的"即时"函数。
- **Moore 输出干净**：Moore 输出只由寄存器状态决定，时钟沿之后一小段传播延迟内就稳定，并保持整整一个时钟周期。Mealy 输出直接挂在输入 $X$ 上：$X$ 在周期中间变了，$Y$ 跟着变；$X$ 上有毛刺，$Y$ 原样透出。如果下游也是同步采样，毛刺通常无害；如果 $Y$ 要出芯片或驱动异步逻辑，就可能出事。
- **Mealy 状态少**：因为输出可以"存"在转移弧上，同样的功能往往省状态（这里 2 对 3）。状态少则触发器少、编码短。

工程上的惯例：**默认用 Moore**。输出与状态同拍、时序好分析、不会把输入毛刺漏出去。Mealy 省的那点状态在现代工艺下几乎不值钱，而时序上的坑是真金白银。如果确实需要 Mealy 的"当拍响应"（比如严格的协议时序），常用折中是**注册的 Mealy（registered Mealy）**：按 Mealy 定义算输出，但把输出再打一拍寄存器送出去——输出变干净了，代价是响应也晚一拍，和 Moore 对齐，但状态数仍可能比 Moore 少。

## 4. 五步设计流程与状态编码

面对一个时序需求，标准动作是五步：

1. **规格**：用自然语言+时序图把功能钉死。最容易漏的是边界情况：允许重叠吗？复位后从哪开始？输入有效窗口是哪一拍？规格含糊，后面全是返工。
2. **状态图**：定义状态（每个状态一个明确含义，"我记住了什么"）、画转移弧、标输出。这是唯一需要创造力的步骤。
3. **状态表**：把状态图机械地翻成真值表：每一行是（现态，输入）→（次态，输出）。状态图里漏掉的转移在这一步会自己暴露——每个现态对每种输入取值都必须有去向。
4. **状态编码**：给每个状态分配一个二进制码。这一步不改变功能，但直接改变电路的规模、速度和功耗。
5. **次态/输出逻辑**：从状态表推出逻辑表达式（手工化简或交给综合器），落成电路或 RTL 代码。

第 4 步的三种主流编码，以 $N$ 个状态为例：

| 编码 | 触发器数 | 次态逻辑 | 每拍翻转位数 | 典型场景 |
|---|---|---|---|---|
| binary | $\lceil\log_2 N\rceil$ | 较复杂（多级门） | 平均约一半 | ASIC、状态多且触发器贵 |
| one-hot | $N$ | 最简单（每个次态比特 = 若干弧的或） | 恒为 2 | FPGA（触发器多、布线贵） |
| Gray | $\lceil\log_2 N\rceil$ | 与 binary 相当 | 顺序转移时为 1 | 低功耗、状态机近似顺序执行 |

几点"为什么"：

- **one-hot 的次态逻辑为什么简单**：one-hot 下每个状态占一个比特 $s_i$，"$s_j$ 为次态"当且仅当"存在一条从某状态指向 $j$ 的弧且该弧条件成立"，所以 $s'_j$ 就是若干条弧条件的逻辑或，几乎没有共享项需要化简。状态多时 binary 编码的次态逻辑是密集的多级与或网络，one-hot 则保持浅而规整。
- **FPGA 为什么偏爱 one-hot**：FPGA 的基本单元里触发器几乎是白送的（每个查找表后面都跟着一个触发器，不用白不用），稀缺的是查找表和布线。one-hot 用触发器换组合逻辑，正好扬长避短；综合器在 FPGA 目标下默认就会把 FSM 重编码成 one-hot。
- **Gray 为什么省功耗**：CMOS 的动态功耗正比于信号翻转次数。Gray 编码保证相邻码只差一比特，若状态机大部分转移发生在"相邻状态"之间（计数器、顺序流程），每拍只有一比特翻转，是 binary 的下限水平。但注意 Gray 只对顺序转移有效，乱跳的状态图救不了——自检问题第 4 题有定量对比。

还要处理一个编码带来的隐藏问题：**未用状态**。$n$ 个触发器有 $2^n$ 个编码，$N < 2^n$ 时剩下的都是"非法状态"。上电噪声、单粒子翻转（第 18 章会细讲）可能把状态机踹进非法状态。对策是在状态表中给非法状态显式指定去向（通常回初始态），或在 RTL 里写 `default` 分支——不写的话，综合器可能把非法态当无关项优化掉，机器一旦掉进去就再也出不来。

## 5. 完整实例：1101 序列检测器（Moore，允许重叠）

现在把五步流程完整走一遍。

**第 1 步，规格**：输入比特流 `din` 每拍一位；当最近收到的 4 位恰为 `1101` 时，输出 `detected` 拉高一个周期。允许重叠：输入 `1101101` 中第 4–7 位也构成 `1101`，要报第二次。同步时钟，异步低有效复位，复位后视为"什么都没收到"。

**第 2 步，状态图**。状态 = "目前已匹配的 1101 的最长前缀"：

- `S0`：什么都没匹配上（空前缀）。收 1 进 `S1`，收 0 留 `S0`。
- `S1`：已匹配 `1`。收 1 进 `S2`，收 0 回 `S0`（`...10` 末尾不是任何前缀的开头）。
- `S2`：已匹配 `11`。收 0 进 `S3`；收 1 **留在 `S2`**——输入变成 `...111`，末尾两位仍是 `11`，匹配进度没有丢。
- `S3`：已匹配 `110`。收 1 进 `S4`（大功告成），收 0 回 `S0`（`...1100` 前功尽弃）。
- `S4`：已匹配 `1101`，输出 1。这是 Moore 机，输出只跟状态走。它的转移要想清楚重叠：收 1 后末尾为 `...11011`，其最长的是 `1101` 前缀的后缀为 `11`，所以去 `S2`；收 0 后末尾为 `...11010`，没有非空匹配，回 `S0`。

**第 3 步，状态表**：

| 现态 | 含义 | din = 0 时次态 | din = 1 时次态 | 输出 |
|---|---|---|---|---|
| S0 | 空 | S0 | S1 | 0 |
| S1 | 1 | S0 | S2 | 0 |
| S2 | 11 | S3 | S2 | 0 |
| S3 | 110 | S0 | S4 | 0 |
| S4 | 1101 | S0 | S2 | 1 |

检查完备性：5 个状态 × 2 种输入 = 10 个格子全部有去向，没有漏。

**第 4 步，状态编码**：选 one-hot，5 个状态用 5 个触发器，$s_i$ 为 1 表示处于 `S_i`：

`S0 = 5'b00001`，`S1 = 5'b00010`，`S2 = 5'b00100`，`S3 = 5'b01000`，`S4 = 5'b10000`。

**第 5 步，次态/输出逻辑**。one-hot 下按"次态比特 = 指向它的弧的或"直接读状态表：

$$s'_0 = \overline{d_{in}}\,(s_0 + s_1 + s_3 + s_4)$$

$$s'_1 = d_{in}\,s_0$$

$$s'_2 = d_{in}\,(s_1 + s_2 + s_4)$$

$$s'_3 = \overline{d_{in}}\,s_2$$

$$s'_4 = d_{in}\,s_3$$

输出只有 `S4` 为 1：

$$detected = s_4$$

五条次态方程各是两三输入的组合，这就是 one-hot"次态逻辑浅"的直观含义。落成可综合的 SystemVerilog，用标准的三段式写法：

```verilog
// 1101 序列检测器：Moore 机，允许重叠，one-hot 编码
module seq_detect_1101 (
    input  logic clk,
    input  logic rst_n,   // 异步复位，低有效
    input  logic din,
    output logic detected
);
    typedef enum logic [4:0] {
        S0 = 5'b00001,   // 空前缀
        S1 = 5'b00010,   // 已匹配 1
        S2 = 5'b00100,   // 已匹配 11
        S3 = 5'b01000,   // 已匹配 110
        S4 = 5'b10000    // 已匹配 1101，输出 1
    } state_t;

    state_t state, next_state;

    // (1) 状态寄存器：整机唯一的时序逻辑
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= S0;
        else        state <= next_state;
    end

    // (2) 次态逻辑：纯组合
    always_comb begin
        case (state)
            S0:      next_state = din ? S1 : S0;
            S1:      next_state = din ? S2 : S0;
            S2:      next_state = din ? S2 : S3;
            S3:      next_state = din ? S4 : S0;
            S4:      next_state = din ? S2 : S0;
            default: next_state = S0;   // 非法状态自恢复
        endcase
    end

    // (3) 输出逻辑：Moore，只看现态
    assign detected = (state == S4);
endmodule
```

三段式不是教条，它和第 2 节的方框图一一对应：

- **每段只干一件事**：时序只在第 (1) 段，组合逻辑在第 (2)(3) 段。读代码的人一眼知道触发器在哪、组合逻辑在哪；综合器也不会被绕晕。
- **次态与现态分离**：`state` 只被非阻塞赋值驱动，`next_state` 是纯粹的中间信号。想改状态转移，只动第 (2) 段；想改输出定义，只动第 (3) 段。
- **一段式的坑**：如果把输出塞进时序块写 `detected <= (state == S4)`，`detected` 会多打一拍寄存器，比规格晚一个周期——自检问题第 5 题让你亲手推出这个错位。一段式在简单场景也能写对，但状态、次态、输出揉在一起后，这类"差一拍"的 bug 极易混入且难以 review。

跑一遍功能自检：输入 `1 1 0 1 1 0 1`，状态轨迹为 S0→S1→S2→S3→S4→S2→S3→S4，`detected` 在第 5 拍和第 8 拍各拉高一次——第二次正是重叠检测（第 4–7 位的 `1101`），规格达成。

## 6. 小结

| 主题 | 要点 |
|---|---|
| FSM 三段结构 | 状态寄存器（唯一记忆）+ 次态逻辑 $f(S,X)$ + 输出逻辑 $g$ |
| Moore | $Y = g(S)$：输出干净、跟状态同拍、晚 Mealy 一拍；工程默认 |
| Mealy | $Y = g(S,X)$：状态少、当拍响应，但输入毛刺直通输出；折中方案是注册的 Mealy |
| 五步流程 | 规格 → 状态图 → 状态表 → 状态编码 → 次态/输出逻辑 |
| 状态编码 | binary 省触发器；one-hot 逻辑浅、FPGA 首选；Gray 顺序转移单比特翻转、省功耗 |
| 非法状态 | $2^n - N$ 个未用编码必须显式指定去向（default 分支），否则可能锁死 |
| 三段式 RTL | 时序/次态/输出三块分离，与硬件结构一一对应，避免"差一拍"类 bug |

一句话收束：**状态是对"过去"的最充分压缩；把时序设计收敛成填表，是 FSM 这套方法的全部价值。**

Moore 版（状态 A/B/C，C 输出 1），初态 A：

| 拍 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 输入 | 0 | 1 | 1 | 1 | 0 |
| 现态 | A | A | B | C | C |
| 输出 | 0 | 0 | 0 | 1 | 1 |

Mealy 版（状态 A/B，输出 = 现态为 B 且输入为 1），初态 A：

| 拍 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 输入 | 0 | 1 | 1 | 1 | 0 |
| 现态 | A | A | B | B | B |
| 输出 | 0 | 0 | 1 | 1 | 0 |

**(a)** 首次输出 1：Mealy 在第 3 拍，Moore 在第 4 拍，差一拍。根源是 Moore 的输出必须经过一次时钟沿（状态先推进到 C）才能变化，而 Mealy 的输出是输入的组合函数，输入到位当拍即变。注意第 5 拍 Moore 仍输出 1（状态还停在 C），Mealy 已归 0——Moore 输出恒为整拍宽，Mealy 输出的宽度跟随输入。

**(b)** Mealy 输出 $Y = (S = B)\cdot X$，$X$ 是组合路径上的直连输入。若 $X$ 在时钟周期中间出现毛刺（比如上游也是组合逻辑、多个输入不同时到达），$Y$ 在采样沿之外就会跟着抖动；下游若在错误的时刻使用 $Y$（异步逻辑、跨时钟域），毛刺就被当成真值。Moore 输出由触发器驱动，只在时钟沿后变化一次，周期内稳定，天然免疫这类问题。

|---|---|---|---|---|
| 1 | 1 | S0 | S1 | 0 |
| 2 | 1 | S1 | S2 | 0 |
| 3 | 0 | S2 | S3 | 0 |
| 4 | 1 | S3 | S4 | 0 |
| 5 | 1 | S4 | S2 | 1 |
| 6 | 0 | S2 | S3 | 0 |
| 7 | 1 | S3 | S4 | 0 |
| 8 | 0 | S4 | S0 | 1 |

输出在第 5 拍与第 8 拍为 1，共两次。

第一次对应第 1–4 位的 `1101`。关键在于第 5 拍的转移 `S4 --1--> S2`：此时已收到的串是 `11011`，其末尾中最长的、同时是 `1101` 之前缀的子串是 `11`（末两位），所以不退回 S0 而退到 S2，保住了重叠匹配的可能。于是第 5–7 位再来 `0 1` 后，第 4–7 位恰好拼成第二个 `1101`，第 8 拍报出第二次。若 S4 的转移画错（比如收 1 回 S1 或 S0），这次重叠检测就丢了——这就是状态图上每条弧都必须用"最长后缀匹配"原则核对的原因。

</details>

**3.** 设计 1101 检测器的 Mealy 版（允许重叠）：给出状态定义、全部转移弧（含弧上输出）、输出逻辑表达式，并说明它为什么比 Moore 版少一个状态。

<details markdown="1"><summary>点击显示答案</summary>

Mealy 版的输出可以挂在转移弧上，"已经凑齐 1101"这件事不需要一个专门的状态来记住——它在 `S3` 收到 1 的那一拍直接由弧输出。因此只需 4 个状态，含义同前：S0（空）、S1（`1`）、S2（`11`）、S3（`110`）。弧标注"输入/输出"：

- S0：`0/0 → S0`，`1/0 → S1`
- S1：`0/0 → S0`，`1/0 → S2`
- S2：`0/0 → S3`，`1/0 → S2`（`...111` 末两位仍是 `11`）
- S3：`0/0 → S0`，`1/1 → S1`（检测到 1101，输出 1；`1101` 的末位 `1` 又是新匹配的开头，故去 S1）

输出逻辑：用 one-hot 或任意编码下现态为 S3 的标志 $s_3$，

$$detected = s_3 \cdot d_{in}$$

对比 Moore 版的 $detected = s_4$：Moore 需要一个独立状态 S4 来"寄存"检测成功这个事实，以便下一拍输出；Mealy 把输出与转移绑定，同一拍内"看见 S3 且输入为 1"就是结论，省掉 S4。一般规律：**检测定长模式的 Moore 机要比 Mealy 机多一个"庆祝状态"**。代价如第 3 节所述：$detected$ 组合地依赖 $d_{in}$，响应提前一拍、宽度不定、毛刺直通。

</details>

**4.** 定量比较三种编码的翻转功耗。(a) 证明 $k$ 位 binary 计数器每次加 1 的平均翻转比特数趋近 2，Gray 计数器恒为 1；(b) 证明 one-hot 编码的 FSM 每次状态转移恰好翻转 2 比特，并据此说明为什么"one-hot 省功耗"是常见误解。

<details markdown="1"><summary>点击显示答案</summary>

**(a)** binary 计数器加 1 时，第 $i$ 位（从 0 计）当且仅当低 $i$ 位全为 1 才翻转，即在所有计数步中每 $2^i$ 步翻一次，翻转概率 $2^{-i}$。期望翻转数

$$\sum_{i=0}^{k-1} 2^{-i} = 2 - 2^{-(k-1)} \xrightarrow{k\to\infty} 2.$$

Gray 码相邻两码只差一比特，顺序计数每步恒翻转 1 比特。CMOS 动态功耗 $P \approx \alpha C V^2 f$ 正比于翻转率 $\alpha$，故顺序计数场景 Gray 比 binary 省约一半翻转。

**(b)** one-hot 下现态码只有一个 1（在 $s_i$），次态码只有一个 1（在 $s_j$）。转移时 $s_i: 1\to0$、$s_j: 0\to1$，其余比特不动——恰好 2 次翻转（自环除外，自环 0 次）。所以"one-hot 每拍只动两根线"听起来很省，但对比要公平：$N$ 状态 one-hot 用 $N$ 个触发器，binary 只用 $\lceil \log_2 N\rceil$ 个，binary 每次转移平均翻转数也只是这个对数量级的一小部分。$N = 16$ 时 one-hot 每拍翻 2 比特但要给 16 个触发器全部提供时钟（时钟网络功耗正比于负载数），binary 平均翻不到 2 比特且只有 4 个触发器。结论：one-hot 的优势在**次态逻辑浅、时序好、FPGA 资源匹配**，不在功耗；拿它当低功耗手段是误解，真正省翻转的是 Gray（且仅对顺序转移）。

</details>

**5.** 有人把 1101 检测器写成一段式：

```verilog
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        state    <= S0;
        detected <= 1'b0;
    end else begin
        case (state)   // 次态转移，同第 5 节
            ...
        endcase
        detected <= (state == S4);
    end
end
```

功能上比三段式错在哪？用第 5 节的输入 `1 1 0 1` 逐拍推演说明，并解释根因。

<details markdown="1"><summary>点击显示答案</summary>

错在输出**晚了一拍**。根因是非阻塞赋值的语义：RHS 在时钟沿到来的**瞬间**用旧值求值。`detected <= (state == S4)` 采样的是沿之前的 `state`，所以 `detected` 反映的是上一拍的状态，比"现态为 S4 时输出 1"的 Moore 规格滞后一个周期。

推演输入 `1 1 0 1`（初态 S0，`detected` 初值 0）：

- 第 1 拍末沿：旧 state = S0，state ← S1，detected ← (S0==S4) = 0；
- 第 2 拍末沿：旧 state = S1，state ← S2，detected ← 0；
- 第 3 拍末沿：旧 state = S2，state ← S3，detected ← 0；
- 第 4 拍末沿：旧 state = S3，state ← S4，detected ← (S3==S4) = 0——**此刻状态已到 S4，输出却还是 0**；
- 第 5 拍末沿：旧 state = S4，state 转移离开，detected ← (S4==S4) = 1——输出比规格晚整整一拍，而且如果第 5 拍输入使状态离开 S4，这个迟到的 1 出现时机器早已不在"检测到"的上下文里，下游按拍对齐的逻辑全部错位。

修法有两条：一段式里改成 `detected <= (next_state == S4)`（用次态预测下一拍的现态，时序对齐，但次态逻辑被迫也进时序块，写法变绕）；或者直接回到三段式——`assign detected = (state == S4)` 是纯组合，现态一进 S4 输出当拍就位，与时序块彻底解耦。这个 bug 的隐蔽之处在于仿真波形"看起来也对"，只是整体平移一拍，不对照规格逐拍核对根本发现不了——这正是三段式把时序与组合物理隔离的价值。

</details>
